# WinSetup — аудит исходников v0.8.1 перед передачей Claude

Дата аудита: 14.11.2026. Основа: архив `WinSetup-v0.8.1-source.zip`, сравнение с v0.8.0, v0.7.2 и v0.7.1.

## Что реально есть в исходниках

- C# / WPF / .NET 10, `WinSetup.csproj`, x64 single-file publish script.
- Встроенный каталог: Discord, Telegram, Chrome, Firefox, Steam, Epic Games Launcher, Zapret Discord, tg-ws-proxy, Happ, ExitLag, GearUP Booster, ShareX.
- Категории, поиск, карточки, выбор нескольких приложений.
- Установка очередью через WinGet; последовательное выполнение, прогресс, отмена, повтор элементов со статусом ошибки.
- Первичная подготовка WinGet: загрузка App Installer с `aka.ms/getwinget`, ограничение размера, проверка Authenticode через PowerShell, запуск штатного установщика Windows с подтверждением пользователя.
- Проверка приложений через uninstall registry и `winget list`; для Firefox/Chrome есть резервные стандартные пути.
- Запрос целевой папки через WinGet `--location`, сохранение корня установки. Это best-effort: пакет/установщик может не поддерживать параметр.
- Личный каталог: добавление, редактирование, удаление; хранение JSON в LocalAppData.
- Профили выбранных приложений; сохранение шаблонных папок и install root.
- Логирование в LocalAppData, открытие журнала, временная папка и очистка.

## Что показало сравнение версий

- v0.7.1 → v0.7.2: исправление вызова `Process.Start`.
- v0.7.2 → v0.8.0: настройка install root, передача `--location`, чтение uninstall registry и показ фактического пути.
- v0.8.0 → v0.8.1: сворачивание части действий в Expander; дополнительная проверка результата установки, fallback-пути Firefox/Chrome.
- v0.8.1 — самый полный из найденных архивов; он и должен оставаться исходной точкой.

## Проблемы и ограничения, которые важно не скрывать

### Архитектура
- `MainWindow.xaml.cs` содержит каталог, фильтрацию, профили, состояния UI, очередь и orchestration. Это слишком много ответственности для одного окна.
- `InstallerService` одновременно отвечает за WinGet, bootstrap, загрузку, проверку подписи, запуск процессов, реестр, определение путей и логирование.
- Нет отдельного слоя каталога/манифестов установщиков и интерфейса провайдера установки. Сейчас основной реальный провайдер — WinGet.
- Встроенный каталог зашит в `LoadCatalog()`. Нет отдельного версионируемого каталога с полями publisher, homepage, source, install strategy и verification strategy.

### Функциональность
- Для Zapret Discord, tg-ws-proxy, Happ, ExitLag и GearUP нет готового безопасного сценария установки; элементы должны честно показывать «требует настройки», а не обещать установку.
- Нет полноценной страницы установленных приложений с действиями Update / Uninstall / Repair.
- Нет каталога доступных обновлений, закрепления версии, исключений из обновлений.
- Нет полноценного импорта/экспорта профиля в переносимый JSON-файл; текущие профили локальные.
- Нет предпросмотра пакета перед установкой (источник, ID, издатель, версия/архитектура/тип установщика, соглашения, аргументы).
- Проверка пути покрывает registry и ограниченные fallback-пути. Это не универсальный детектор для всех MSI/EXE/MSIX/portable приложений.
- Успешный exit code WinGet при неизвестном фактическом пути может приводить к статусу «Установлена · путь не определён». UI должен чётко отделять «команда завершилась успешно» от «наличие приложения независимо подтверждено».
- Очередь последовательная, но нет полноценной модели задачи с отдельными этапами Download / Verify / Install / Detect / Cleanup и структурированным результатом.

### Интерфейс
- Верхняя зона всё ещё содержит два Expander-а с большим количеством кнопок; это лучше прежней полосы, но не финальная информационная архитектура.
- Карточки используют одинаковую заглушку `APP`, а не логотипы или аккуратные буквенные fallback-иконки.
- Карточки имеют фиксированную ширину 350 px; компоновка не является полноценной адаптивной сеткой.
- Действия личного приложения встроены в нижнюю часть карточки, что добавляет шум.
- Левая навигация сейчас содержит категории, но не разделы «Установленные», «Обновления», «Очередь», «Профили/настройки».
- Нижняя панель смешивает общий статус, путь установки, подробный вывод, прогресс и кнопки. Её следует превратить в компактную очередь/панель выполнения с раскрываемыми деталями.
- Визуальные токены частично централизованы в App.xaml, но много цветов/размеров прямо прописано в XAML.

## Что НЕ нужно делать

- Не выдавать проект за готовый публичный релиз.
- Не менять package IDs без онлайн-проверки точного ID, издателя и источника.
- Не реализовывать «установку GitHub проекта» простым скачиванием и запуском случайного `.bat`, `.ps1` или архива.
- Не обещать, что все приложения можно установить на `D:\Programs`. `--location` — только запрос, если конкретный installer поддерживает custom location.
- Не запускать несколько установщиков параллельно без явной модели конфликтов и ограничений.
- Не переносить установленное приложение вручную после установки.
- Не добавлять выдуманные рейтинги, размеры загрузки, версии, логотипы или статусы.
- Не переписывать бизнес-логику одновременно с визуальным редизайном без отдельного согласованного этапа и регрессионных тестов.

## v0.8.5 installation folder behavior
The selected directory is a parent/root. Each application must be installed into its own sanitized child folder named after the catalog entry. Current implementation uses per-app child paths, a Firefox `/InstallDirectoryPath` override, and a VLC WiX MSI `APPLICATIONFOLDER` override. Post-install verification must compare the actual location to that exact child folder. Preserve this behavior during UI refactoring; do not revert to one shared folder or claim generic support for installers that ignore custom paths.
