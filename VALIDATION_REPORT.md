# Talia 1.0.0 — отчёт о проверке

Дата сборки пакета: 2026-11-15. Среда: Linux, .NET SDK 10.0.115, **без Windows, без WPF-сборки, без доступа к NuGet**.

## Главное
- **Приложение целиком НЕ собрано и НЕ запускалось.** WPF-проект (`WinSetup.csproj`) не удалось даже восстановить: пакет Windows Desktop Reference Pack скачивается с NuGet, а сеть к нему недоступна. `dotnet restore`/`publish` для win-x64 не выполнялись, **готового EXE нет**.
- Слои без WPF (`Models/*`, `Services/*`) **скомпилированы на .NET 10 без ошибок** и проверены 41 автоматической проверкой (все прошли, запускалось дважды).
- XAML, окна, стили и код `MainWindow*.cs` / `TaliaDialog` / `AddAppWindow` / `FolderSettingsWindow` / `UI/UiHelpers.cs` компилятором **не проверялись** — только статически (см. ниже). Ожидай мелкие ошибки при первой сборке.

## Что НЕ проверялось (не отмечено как пройденное)
Пункты списка из задания, которые требуют Windows/WPF/WinGet, **не выполнены**:

1. Запуск приложения, Home, каталог, поиск, категории, выбор нескольких программ.
2. Добавление/редактирование/удаление пользовательских программ **через интерфейс** (логика «на месте» и сохранения проверена только на уровне модели и хранилища).
3. Сохранение каталога после перезапуска (на уровне файлов проверено, в приложении — нет).
4. Создание/загрузка/удаление профилей и диалоги импорта/экспорта в UI (логика файлов проверена).
5. Выбор корневой папки, создание папок приложений.
6. Обнаружение WinGet, установка WinGet, установка приложений, обнаружение уже установленных, проверка фактического пути, отмена, повтор ошибок, открытие журнала, очистка временных файлов.
7. Раздел «Установленные» (чтение реестра `InstalledAppsScanner` на Linux невозможно — Windows-реестр).
8. Адаптивность на 880×560 … максимум, DPI 100/125/150/200 %, фокус клавиатуры, подсказки, все диалоги.
9. Реальные изменения установщика: проверка исполняемого файла, статус «Установлена · другой путь», таймауты, завершение дерева процессов, ужесточённая проверка подписи.

## Исправления относительно 0.9.0 (подтверждены чтением кода)
См. `CHANGELOG.md`, раздел 1.0.0. Кратко: редактирование без потери данных; runtime-состояние не сохраняется на диск; пропущенные пользовательские записи не теряются; защита от повреждения JSON; «Повторить ошибки» запускает только ошибки; сканирование вне UI-потока; установка засчитывается только при подтверждённом исполняемом файле; неудачный запуск не маскируется старой копией; другой путь — предупреждение, а не ошибка; строгая проверка подписи Microsoft; таймауты и закрытие окна во время установки.

## Раздел «Обновления» — не добавлен
`winget upgrade` выдаёт локализованный текстовый вывод без стабильного машиночитаемого формата; надёжно распарсить его на всех языках Windows нельзя, а модуль Microsoft.WinGet.Client не гарантирован. Фиктивных обновлений и кнопок Update/Uninstall/Repair нет.

## Как проверить на Windows
```powershell
dotnet restore WinSetup.csproj
dotnet build WinSetup.csproj -c Release
$env:LOCALAPPDATA = "$env:TEMP\talia-checks"; dotnet run --project Tests\Talia.LogicChecks   # 41 проверка логики
.\Publish-Portable.ps1                                                                      # портативный EXE
```
Затем пройди чек-лист из `TALIA_UI_NOTES.md` и список «Что НЕ проверялось» выше.

## Известные ограничения
- Интерфейс остаётся на русском (как и тексты статусов движка).
- Реестр-сканирование не видит приложения из Microsoft Store (MSIX) и портативные программы без записи удаления.
- Проверка «установлено» для программ вне Firefox/VLC/Chrome опирается на найденный `.exe` в папке/значке записи реестра — это достоверное, но не абсолютное доказательство.
- TOCTOU между проверкой подписи App Installer и его запуском смягчён только тем, что временная папка уникальна для процесса.
